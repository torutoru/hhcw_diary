## 3. 꼭 기억할 규칙과 결정

### 서비스 이름
- **환경변수로만 관리합니다.** 프론트 `VITE_APP_NAME`(Netlify, **빌드할 때** 들어감 → 바꾸면 다시 배포) + 백엔드 `APP_NAME`(Render, 알림 제목·승인 메일). 둘 다 같은 값으로 맞춥니다.
- 화면 코드에서는 "우리가족"을 직접 쓰지 말고 `APP_NAME`([frontend/src/lib/app.ts](../frontend/src/lib/app.ts))을 쓰고, 조사는 `withObject()`로 받침에 맞춥니다. `index.html`은 `__APP_NAME__` 자리표시를 빌드 때 바꿉니다([vite.config.ts](../frontend/vite.config.ts)).
- 이름을 바꾸면 **아이폰에 이미 설치된 앱은 이름이 안 바뀝니다**(지우고 다시 설치).

### 사용자 정보와 권한
- **가족관계**(`users.relation`): 권한 기준이고 수정할 수 없습니다. '엄마'·'아빠' → `parent`(관리자: 피드 작성·수정, 구성원 관리). DB 부분 고유 인덱스 `uniq_parent_relation`으로 한 명씩만 허용
- **호칭**(`users.nickname`): 화면에 보이는 이름이고 내 정보에서 수정할 수 있습니다. 댓글 등에서 `<PersonName>`으로 "호칭 + 작은 가족관계"를 표시합니다 ([Person.tsx](../frontend/src/components/Person.tsx)).
- 권한은 매 요청 DB에서 다시 읽습니다. 서버 시작 시 `role`을 가족관계 기준으로 다시 맞춥니다.

### 데이터 삭제는 모두 soft delete
- 구성원 제거: `users.removed_at` 기록, `status='pending'`, 남은 승인 링크 무효화. 재가입 요청으로 돌아올 수 있음
- 댓글 삭제: `comments.deleted_at` 기록, 본문은 비움. 목록에는 "작성자의 요청으로 댓글이 삭제되었습니다"
- 사진: DB 행을 먼저 지우고(DB가 기준) R2 파일을 지움. 실패하면 `storage_deletions`에 기록

### DB 마이그레이션 방식
- 별도 도구 없이 [backend/src/db/migrate.ts](../backend/src/db/migrate.ts)가 **서버 시작 시** 실행됩니다.
- 새 테이블: `CREATE TABLE IF NOT EXISTS` / 기존 테이블에 컬럼 추가: `addColumnIfMissing()` (PRAGMA로 확인 후 ALTER)
- 운영 Turso에도 배포하면 자동으로 적용되므로, **되돌릴 수 없는 변경인지** 먼저 생각해야 합니다.

> ⚠️ `1f0b95a`에서 `users.name` → `relation`으로 컬럼 이름을 바꿨습니다. **이 커밋 이전 버전의 백엔드로 롤백하면 동작하지 않습니다.**

### 푸시 알림
- 받는 사람: **새 피드** → 올린 사람을 뺀 가족 모두(지난 날짜 포함) / **새 댓글** → 피드 작성자 + 그 피드에 (지우지 않은) 댓글을 단 사람, 본인 제외. 피드 수정·댓글 삭제는 알림 없음
- 같은 피드 댓글 알림은 `tag`로 묶어 "새 댓글 N개"로 덮어씁니다. 알림을 누르면 새 피드는 `/feeds/:id`, 댓글은 `/feeds/:id#comments`(최신 댓글로 스크롤: `.modal-body.scrollTop`을 직접 맨 아래로, 그린 직후·0.3초·0.9초에 맞춤. `scrollIntoView`는 휴대폰의 떠 있는 창 안에서 무시되는 경우가 있어 쓰지 않음). 앱이 켜져 있으면 서비스 워커 → `OPEN_URL` 메시지 → 앱 안에서 이동(`client.navigate`는 아이폰에서 불안정해서 쓰지 않음).
- 아이콘 배지는 개수가 아니라 **"1"(새 소식 있음)**. 안드로이드 크롬은 배지 API를 지원하지 않아 런처가 알림을 보고 점·숫자를 붙입니다. 앱을 열면 배지·알림을 지웁니다.
- 알림은 **기기마다** 켭니다(내 정보 → 알림). 로그아웃하면 그 기기 구독 해제, 다시 로그인하면 이전에 켠 기기는 자동 재연결. 아이폰은 **홈 화면 설치 + iOS 16.4 이상**에서만 됩니다.
- **VAPID 키는 한 번 정하면 바꾸지 않습니다**(바꾸면 모든 기기 구독 무효). 운영 키는 Render에만 있고, 로컬 `backend/.env`에는 로컬 전용 키가 있습니다. Netlify에는 필요 없습니다(프론트는 `/api/push/public-key`로 받음).

### PWA
- 서비스 워커는 직접 작성하는 방식(injectManifest, [frontend/src/sw.ts](../frontend/src/sw.ts))입니다. 화면 파일·글꼴만 캐시하고 **`/api` 응답과 사진은 캐시하지 않습니다.**
- 서비스 워커가 `/api/*` 이동을 가로채지 않게 `NavigationRoute`의 `denylist`를 꼭 유지합니다(승인 메일 링크가 서버로 가야 함).
- 새 버전은 "새 버전이 있어요 → 새로고침"을 눌러야 적용됩니다(작성 중 강제 새로고침 방지).
- 사이트 주소(도메인)를 바꾸면 설치된 앱을 모두 다시 설치·로그인해야 합니다.

### 보안 관련 결정
- **로그인 잠금**: 비밀번호 5번 연속 실패 → 1시간 잠금, 성공하거나 1시간이 지나면 횟수 초기화 ([architecture.md](architecture.md#인증)). 실패 문구에 남은 횟수를 보여주는데, 이는 그 이메일이 가입돼 있다는 걸 알려주는 셈입니다. 가족 전용·관리자 승인 서비스라 편의를 택했습니다.
- **비밀번호는 브라우저에 저장하지 않습니다.** "기억하기"는 아이디(localStorage) + 400일 httpOnly 쿠키입니다. 사용자는 비밀번호까지 저장하길 원했지만, 평문 저장의 위험을 설명하고 이 방식으로 합의했습니다.
- R2 버킷은 비공개이고, 사진은 2시간짜리 서명 URL로만 보여줍니다. 서명 시각을 1시간 단위로 맞춰 브라우저 캐시가 동작합니다. `R2_PUBLIC_URL`은 비워 둡니다.
- 사진 업로드 시 EXIF(위치정보 등)를 제거합니다.

### 사진 두 벌
- 원본(2048px, 크게 보기용)과 리스트용(1080px, 카드·가로 스크롤·미리보기용)을 함께 저장합니다. 새로 사진을 쓰는 화면을 만들 때 **작게 보이는 곳은 `thumbUrl`**, 크게 보는 곳만 `url`을 씁니다.
- 리스트용은 이 기능 이후 올린 사진에만 있습니다. 기존 사진은 `thumb_key`가 비어 있어 원본을 대신 씁니다(사용자 결정: 기존 사진이 적어 변환 작업은 두지 않음). 쿼리에서 리스트용을 쓸 때는 항상 `COALESCE(thumb_key, storage_key)`로 원본 대체를 유지합니다.
- 사진을 지우는 코드를 새로 만들면 `imageKeys(row)`로 두 파일을 함께 지웁니다.

### 로딩 화면
- 앱을 열 때 로그인 확인과 메인 피드 첫 불러오기에서는 **가족 문구**(사용자 작성 20개, [frontend/src/lib/familyQuotes.ts](../frontend/src/lib/familyQuotes.ts))를 6초마다 은은하게 바꿔 보여줍니다([LoadingQuotes.tsx](../frontend/src/components/LoadingQuotes.tsx)). 0.4초 안에 끝나면 보여주지 않고, 5초가 넘으면 "서버를 깨우고 있어요"로 바뀝니다(Render 무료 플랜 잠들기 대응). 두 로딩이 이어지면 같은 문구를 이어 갑니다.
- 다음 10개는 바닥 1200px 전에 미리 불러오고, 그동안 아래쪽에 작은 스피너. 끝까지 보면 "모든 피드를 다 봤어요".
- **당겨서 새로고침**([usePullToRefresh.ts](../frontend/src/lib/usePullToRefresh.ts)): 메인 피드 맨 위에서 아래로 당기면 목록이 따라 내려오고(저항 0.5, 최대 120px), **드러난 위쪽 빈 공간(배경)**에 "불러오는 중"과 같은 모양(작은 아이콘 + 회색 글자)으로 "당겨서 새로고침" → "놓으면 새로고침"(초록)이 보임. 처음엔 흰 원형 버튼으로 떠 있게 만들었다가 "이질적"이라는 사용자 의견으로 바꿈. **놓으면** 목록은 바로 제자리로 올라가고, 새로고침 동안 **화면 전체를 투명한 옅은 회색이 덮고 가운데 진행 표시**(`.refresh-overlay`, 화면 누르기 차단). **1초가 넘으면** 서버(Render)가 깨는 중으로 보고 **짙은 회색(`.is-slow`)으로 바뀌며 첫 로딩과 같은 가족 문구 + 작은 진행 표시**(`<LoadingQuotes immediate />`, 5초 더 지나면 "서버를 깨우고 있어요…")를 띄움(사용자 요청: 느릴 때 진행 표시만 계속 돌아서. 처음부터 문구를 띄우거나 최소 2초로 늘리는 안은 빠른 새로고침이 답답해서 버림). 72px 이상 당기고 놓으면 최신 피드부터 다시 불러옴(최소 0.5초). 상세가 열려 있으면 쉼. 당기는 동안 `touchmove`를 `preventDefault`(passive: false)하고, 피드 화면에서는 `overscroll-behavior-y: contain`으로 브라우저 기본 당겨서 새로고침을 끕니다.
- 화면 안의 로딩은 글자 대신 **깜빡이는 스켈레톤**(`.skeleton` 애니메이션)을 실제 화면과 같은 자리에 보여줍니다. "불러오는 중"은 화면 읽기 기능용(`sr-only`)으로만 남깁니다.
  - 달력(피드 검색하기·작성하기): 피드 있는 날을 불러오는 동안 **날짜 칸 자체가 깜빡임**(`.calendar-grid.is-loading`). 달을 바꾸면 이전 달 점을 먼저 비움(같은 날짜에 잘못된 점이 잠깐 보이던 문제).
  - 피드 상세(`DetailSkeleton`), 가족 구성원 관리(`MembersSkeleton`), 내 정보의 알림 칸(`NotificationSettings`)
  - 아직 글자로 남은 곳: 피드 작성·수정 화면(`ComposePage`)
- 버튼 안의 진행 표시는 **점이 . → .. → ... 로 계속 바뀌는 글자**([LoadingText.tsx](../frontend/src/components/LoadingText.tsx))를 씁니다(지금은 로그인 버튼). 요청이 5초 넘게 걸리면(`useSlow`) "서버를 깨우고 있어요" 안내를 함께 보여줍니다(Render 잠들기, 사용자 제보: 로그인 중으로만 멈춰 보여 실패인지 진행 중인지 구분이 안 됨).
- 문구를 바꾸려면 `familyQuotes.ts`만 고치면 됩니다(따옴표 없이). 14번 "세상 이풍파"는 사용자 원문 그대로입니다.

### 안 본 피드·댓글 "N"
- 메인 피드 카드 날짜 옆: 안 본 남의 새 피드(`isNew`)이거나 마지막으로 본 뒤 남의 새 댓글(`newComments`)이 있으면 빨간 N([NewBadge.tsx](../frontend/src/components/NewBadge.tsx)).
- 상세를 열면 `POST /feeds/:id/read`로 읽음 처리 → 카드의 N이 바로 사라지고(`onFeedRead`), 상세에서는 이전에 본 시각 뒤에 달린 남의 댓글 이름 옆에 N(열어 둔 동안 유지).
- 기준 시각 `users.read_baseline_at`: 기능이 처음 배포될 때 기존 사용자는 그 시각으로 채워 **배포 순간 모든 피드에 N이 붙지 않게** 했고, 새 사용자는 승인 시각. 그 전 피드·댓글은 본 것으로 칩니다. 내가 쓴 피드·댓글은 세지 않습니다.

### 플로팅 버튼과 달력
- 오른쪽 아래 플로팅 버튼([FabMenu.tsx](../frontend/src/components/FabMenu.tsx)): 일반 사용자는 돋보기 → `/search`. 엄마·아빠는 ＋ → 누르면 ×로 돌며 "피드 작성하기"(`/compose`)·"피드 검색하기"(`/search`)가 펼쳐짐. 뒤 배경 누르기·Esc로 접힘
- 달력은 공용 부품([MonthCalendar.tsx](../frontend/src/components/MonthCalendar.tsx))을 작성하기(오늘까지 모든 날)와 검색하기(피드 있는 날만)가 함께 씁니다. 차이는 `isEnabled`·`onPick`·안내 문구뿐입니다.
- 상세 모달은 열었던 화면으로 돌아갑니다(`FeedOutletContext.closeTo`: 메인 피드 `/` 또는 검색 달력 `/search`). 검색 달력은 모달이 떠 있는 동안에도 계속 떠 있어서 보던 달이 유지됩니다.
- 상세의 날짜 옆 **"수정하기"**(엄마·아빠만) → `/compose/:date`에 `state.returnTo`를 넘깁니다. 수정 화면은 `returnTo`가 있으면 저장·취소 후 `navigate(-1)`로 그 상세에 돌아갑니다(뒤로 가기 기록이 겹치지 않게). 달력에서 들어온 경우는 예전대로 취소 → 달력, 저장 → 메인 피드.

### 메뉴·확인 UI 통일
- 무언가에 대한 동작 목록은 **⋯ 버튼 → 버튼 바로 위에 뜨는 작은 메뉴**([PopoverMenu.tsx](../frontend/src/components/PopoverMenu.tsx), 프로필 메뉴와 같은 카드 모양), 되돌릴 수 없는 동작의 확인은 **확인 시트**([ConfirmSheet.tsx](../frontend/src/components/ConfirmSheet.tsx))로 통일합니다.
  - 아래에서 올라오는 메뉴 시트는 써 봤다가 "별도 다이얼로그처럼 보인다"는 사용자 의견으로 팝오버로 바꿨습니다.
  - 팝오버는 스크롤 영역에 잘리지 않게 화면 좌표(`position: fixed`)로 띄우고, 위에 공간이 없으면 버튼 아래에 붙습니다. 바깥 누르기·Esc·스크롤·화면 크기 변경 시 닫힙니다(상세 모달 위에서 Esc는 메뉴만 닫음).
- 내 댓글: ⋯ → "수정하기" / "제거하기"(빨간색) → 제거는 확인 시트. 수정은 **맨 아래 댓글 입력칸**에 원래 내용을 채우고 위에 "댓글 수정 중 · 취소" 줄을 띄워, 보내기(✓)로 저장합니다(메신저 방식). 고친 댓글은 시간 옆 "· 수정됨".
- 댓글은 **시간순**(오래된 것 → 최신, 맨 아래가 최신). 잠깐 최신순으로 바꿨다가 사용자 요청으로 아래 구조로 정리:
  - 메인 카드: **가장 최근 댓글 1개**, 이전 댓글이 있으면 그 위에 "댓글 N개 더보기".
  - 상세: 피드 내용 아래에 **최근 3개**만. 더 있으면 그 위 "이전 댓글 N개 보기" → **댓글 영역 펼침**(`.comments-panel`): 피드 내용은 맨 위 한 줄 요약(누르면 다시 접힘), 아래는 댓글만 따로 스크롤. 맨 아래(최신)에서 시작하고, 위로 올리면(맨 위 160px 전) 이전 댓글 20개씩 자동으로 붙음. 붙일 때 늘어난 높이만큼 scrollTop 을 보정해(useLayoutEffect) 보던 댓글이 제자리에 있음. 불러오는 동안 맨 위에 댓글 스켈레톤.
  - API 는 offset 대신 `before=<댓글 id>` 기준(보는 사이 새 댓글이 달려도 겹치거나 빠지지 않음). 내가 댓글을 달면 맨 아래로 이동.
- 피드 작성·수정의 "사진 더하기": 사진을 **길게 누르면**(0.5초, [useLongPress.ts](../frontend/src/lib/useLongPress.ts)) 사진 위에 팝오버 → "대표 사진으로 적용하기" → 그 사진과 대표 사진의 **자리를 맞바꿈**(서버는 저장 시 `imageIds` 첫 번째가 대표라 변경 없음). 아이폰 사파리는 길게 눌러도 `contextmenu`가 없어 타이머로 재고(10px 넘게 움직이면 취소), 안드로이드·PC 는 `contextmenu`로도 엶. 휴대폰 기본 이미지 메뉴는 `-webkit-touch-callout: none`으로 막음. 올리는 중에 자리를 바꿔도 업로드 결과는 key 로 양쪽(대표·추가)에서 찾아 반영.

### 스크롤 잠금과 화면 확대
- 피드 상세 모달이 떠 있는 동안 뒤 페이지는 [lib/scrollLock.ts](../frontend/src/lib/scrollLock.ts)로 **body 를 position: fixed 로 고정**했다가 닫을 때 보던 위치로 되돌립니다. `overflow: hidden`만으로는 아이폰에서 모달을 끌 때 뒤 목록까지 움직였습니다(사용자 제보). 모달·댓글 영역에는 `overscroll-behavior: contain`.
- **앱 화면 확대는 막고 사진 크게 보기에서만 확대**(사용자 결정): `html, body { touch-action: pan-x pan-y }`, viewport `maximum-scale=1, user-scalable=no`, `gesturestart` 차단(main.tsx). 라이트박스 확대는 라이브러리가 터치 이벤트로 직접 처리해서 영향 없음. 덤으로 아이폰에서 입력칸을 누를 때 저절로 확대되던 현상도 사라짐.
  - 그 대안으로 아래 "글자 크기" 설정을 만들었습니다(아이폰 홈 화면 앱은 시스템 글자 크기가 웹 화면에 반영되지 않음).

### 글자 크기 설정
- 내 정보 > 글자 크기: **작게 75% · 보통 100% · 크게 125%**. 버튼마다 "가"를 실제 크기(22px 기준 16.5/22/27.5px, 현재 설정과 무관하게 고정)로 보여 줍니다. 누르면 바로 적용·저장(`PATCH /api/auth/me { fontSize }`, `users.font_size`), 실패하면 원래 크기로 되돌림.
- 구현: CSS의 모든 `font-size`가 `calc(Npx * var(--font-scale))`이고, [lib/fontSize.ts](../frontend/src/lib/fontSize.ts)가 `<html>`의 `--font-scale`만 바꿉니다. **글자만** 바뀌고 버튼·입력칸·사진 크기는 그대로(화면 전체 배율 확대는 폭이 넘쳐 가로 스크롤이 생김). **새 스타일을 쓸 때 font-size 는 반드시 이 형식으로.**
- 이 기기 localStorage(`hhcw_font_size`)에도 기억해 두고 main.tsx 에서 먼저 적용 → 서버 응답 전 첫 화면·로그인 화면도 같은 크기. 로그인하면 계정 설정으로 덮어씀.

### 사진 크게 보기 (라이트박스)
- 사진 넘기기는 가로 스크롤(`scroll-snap`), 확대는 `react-zoom-pan-pinch`([Lightbox.tsx](../frontend/src/components/Lightbox.tsx)). 핀치·두 번 탭(약 2.5배)·PC 휠, 최대 4배.
- **확대 중에는 가로 스크롤을 끕니다**(`.lightbox-track.is-zoomed`). 예전에는 브라우저의 페이지 확대만 있어서, 확대 후 좌우로 끌면 가로 스크롤이 움직임을 가져가 사진이 넘어갔습니다(사용자 제보).
- 확대 중 **끌기를 시작할 때 이미 그 방향 가장자리**였고 손가락을 60px 이상 움직이면 이전·다음 사진으로 넘깁니다(가장자리 튕김 효과 때문에 손을 뗀 시점이 아니라 시작 시점으로 판단). 넘기면 확대는 풀립니다.
- 원래 크기에서는 라이브러리의 끌기를 꺼서(`panning.disabled`) 스와이프 넘기기가 그대로 동작합니다.
- 브라우저의 **화면 전체 확대**는 `.lightbox { touch-action: pan-x pan-y }`와 `gesturestart` 차단으로 막습니다. 화면 전체가 확대되면 넘긴 사진까지 확대돼 보입니다(사용자 제보).
- 사진이 바뀌면(`index` 변경) 새로 보게 된 사진을 포함해 모든 사진의 확대를 초기화합니다.
- **확대 해제는 `resetTransform(0)`이 아니라 `resetTransform(1)`(`resetZoom`)**로 합니다. 0은 값만 바꾸고 진행 중인 애니메이션(손을 뗀 뒤 위치 맞춤)을 멈추지 않아서, 그 애니메이션이 예전 확대 값을 다시 적용합니다(사용자 제보: 확대 → 다음 사진 → 돌아오면 첫 사진이 확대된 채). 0이 아닌 값이면 라이브러리가 기존 애니메이션을 먼저 취소합니다.

### 날짜
- "오늘" 판단과 `feed_date`는 **한국 시간(KST)** 기준이고, 시각 값은 UTC ISO 문자열입니다.
- 피드는 **날짜마다 하나**(`feeds.feed_date` UNIQUE)이고, 미래 날짜는 서버에서 막습니다.

## 4. 작업 방식 (사용자와 합의한 것)

- **Git**: 혼자 쓰는 저장소이므로 브랜치를 만들지 말고 **`main`에 바로 커밋·푸시**합니다. 커밋·푸시는 사용자가 요청할 때만 합니다.
  - 사용자가 GitHub에서 직접 병합하는 경우가 있으니, 푸시 전에 `git fetch` 후 뒤처졌으면 `rebase`합니다.
- 사용자는 기능을 받으면 **로컬에서 직접 확인한 뒤** "반영해줘", "배포해줘"라고 요청합니다. 확인 전에는 커밋하지 않습니다.
- 디자인 변경은 사용자가 아티팩트에 먼저 그리고 "보고 알려줘"라고 요청합니다. 아티팩트를 읽고 차이를 설명한 뒤 구현하고, 바뀐 시안은 `docs/design/artboards/`에 복사합니다.
- 커밋 메시지는 한국어 제목 + 변경 요약 목록 형식이고, 마지막 줄에 `Co-Authored-By`를 붙입니다.
- 기능을 바꾸면 `docs/`의 관련 문서(api, architecture, pwa, design/README, 이 노트)도 함께 고칩니다.

## 5. 함정과 해결법 (실제로 겪은 것)

### Windows PowerShell 5.1
- **커밋 메시지에 큰따옴표(")가 있으면** `git commit -m @'...'@`가 깨집니다(pathspec 오류). → 메시지를 임시 파일로 써서 `git commit -F <파일>`로 넘깁니다(지금은 항상 이 방식).
- **`git push`가 종료 코드 255나 빨간 오류처럼 보여도** 진행 메시지가 stderr로 나온 것일 뿐입니다. `abc..def main -> main` 줄이 있으면 성공입니다. `cmd /c "git push origin main 2>&1"`로 실행하면 덜 헷갈립니다.
- **`$env:X = ''`는 변수를 지웁니다.** 빈 값으로 덮어쓰는 효과가 없어서 `.env` 값이 그대로 쓰입니다(실제 메일이 나갈 뻔함). 테스트용 설정은 별도 폴더의 `.env`로 분리합니다(6번).
- `Get-Content`는 기본 인코딩이 달라 한글이 깨져 보입니다. 파일 내용 확인은 `-Encoding utf8`을 붙입니다. `Set-Content -Encoding utf8`은 BOM을 붙입니다.
- Git Bash의 `openssl -subj "/CN=..."`은 경로로 바뀌어 깨집니다 → `MSYS_NO_PATHCONV=1`.
- 시험 스크립트에서 `sharp('<파일 경로>')`로 `.uploads` 파일을 열면 Windows에서 파일이 잠겨, 서버의 삭제가 `EBUSY`로 실패합니다. 크기 확인은 `readFileSync` 후 버퍼로 넘기거나, 실패해도 `storage_deletions` 재시도로 정리됩니다.

### 개발 서버
- **개발 서버가 켜진 상태에서 브랜치를 바꾸면** Vite가 `vite.config.ts`가 잠깐 없는 순간에 재시작해서 `/api` 프록시가 빠집니다(로그인 404). → 브랜치 전환 뒤에는 프론트 개발 서버를 다시 켭니다.
- 백엔드 `npm run dev`(tsx watch)는 소스가 바뀌면 재시작하고, **그때마다 마이그레이션이 로컬 DB에 적용됩니다.** `.env`만 바꿨을 때는 재시작되지 않으니 `src/index.ts` 수정 시각을 바꾸는 등으로 재시작합니다.
- 백엔드는 `0.0.0.0:4000`, 프론트는 `localhost:5173`, 미리보기는 `localhost:4173`입니다. 첫 기동은 몇 초 걸리니 health 체크를 재시도합니다.
- `vite.config.ts`도 앱 tsconfig로 타입 검사되는데 Node 타입이 없습니다 → `process` 대신 `loadEnv(mode, '.', 'VITE_')`처럼 씁니다.

### 배포
- Render는 `NODE_ENV=production`이면 devDependencies를 빼고 설치하므로, 빌드 명령은 `npm ci --include=dev && npm run build`입니다([render.yaml](../render.yaml)).
- Render 무료 플랜은 SMTP가 막혀 있어서 메일은 Resend HTTP API로 보냅니다.
- Render 무료 플랜은 15분 동안 요청이 없으면 잠들고, 깨어날 때 첫 요청이 30초 이상 걸릴 수 있습니다. 매 정각 정리 작업도 잠든 동안에는 돌지 않습니다(시작 시 실행으로 보완).
- 프론트 오류 문구 "서버에 연결하지 못했어요. (상태코드)"는 응답이 JSON이 아니라는 뜻입니다. 백엔드까지 가지 못한 것이니 **프록시 주소나 서버 상태부터** 봅니다.
- Netlify 환경변수를 바꾼 뒤에는 **Trigger deploy**로 다시 빌드해야 반영됩니다. 푸시와 동시에 변수를 넣으면 이전 값으로 빌드될 수 있습니다.
- 사이트 오른쪽 아래 Netlify 아이콘은 우리 코드가 아니라 Netlify Drawer(협업 툴바)입니다. 로그인한 관리자·미리보기 주소에서만 보이며, Netlify 설정에서 끌 수 있습니다.

### PWA·푸시
- `npm run dev`(5173)에서는 서비스 워커가 돌지 않습니다. PWA·알림 확인은 `npm run build` 후 `npx vite preview --port 4173`.
- `src/sw.ts`는 워커 환경이라 `tsconfig.sw.json`으로 따로 타입 검사합니다(`npm run typecheck`가 둘 다 실행). 앱 tsconfig에서는 제외되어 있습니다.
- 휴대폰은 HTTPS가 필요해서 로컬(같은 와이파이 `http://PC주소`)로는 설치·알림 시험이 안 됩니다. 배포 후 확인합니다.
- 설치 안내는 기기별로 다릅니다(`useInstallMode`): 안드로이드 크롬 설치 창 / 아이폰 공유→홈 화면에 추가 / **카카오톡 등 앱 안 브라우저는 설치 불가** → 다른 브라우저로 열기 안내 / PC 주소창 설치 아이콘.

### Fastify
- `disableRequestLogging: true`가 현재 버전에서 deprecation 경고(FSTDEP023)를 냅니다. Fastify 5에서는 동작하고, 6으로 올릴 때 바꿔야 합니다.

## 6. 로컬에서 시험하는 방법

- **로컬 계정** (`backend/local.db`, 비밀번호 모두 `1234`)

  | 이메일 | 가족관계 | 권한 |
  | --- | --- | --- |
  | `mom@example.com` | 엄마 | 관리자 |
  | `dad@example.com` | 아빠 | 관리자 |
  | `kid@example.com` | 큰딸 | 일반 |

- `backend/.env`에는 **실제 Resend 키**와 **로컬 전용 VAPID 키**가 들어 있습니다. 로컬 4000번 서버로 가입 요청을 보내면 진짜 메일이 나갑니다.
- 로컬 화면에서 서비스 이름을 바꿔 보려면 `frontend/.env`에 `VITE_APP_NAME=...`을 넣고 개발 서버를 다시 켭니다([frontend/.env.example](../frontend/.env.example)).
- **메일 없는 테스트 서버** 띄우는 법:
  1. 임시 폴더에 `backend/.env.example`을 복사해 `.env`를 만들고 `PORT=4100`, `JWT_SECRET=<32자 이상>`, `TURSO_DATABASE_URL=file:C:/workspace/hhcw_diary/backend/local.db`로 바꿉니다. `RESEND_API_KEY`는 비워 둡니다.
  2. 그 폴더에서 `node C:\workspace\hhcw_diary\backend\node_modules\tsx\dist\cli.mjs C:\workspace\hhcw_diary\backend\src\index.ts`를 실행합니다.
  3. `http://localhost:4100/api`로 요청하면 메일 내용이 서버 로그에만 찍힙니다.
- **푸시 받는 사람 시험**: 로컬에 가짜 HTTPS 푸시 서버(자체 서명 인증서, 받은 요청 경로 기록)를 띄우고, 테스트 서버 `.env`에 테스트용 VAPID 키와 `NODE_TLS_REJECT_UNAUTHORIZED=0`을 넣습니다. 구독은 `crypto.createECDH('prime256v1')`로 만든 가짜 키로 `/api/push/subscribe`에 등록합니다.
- API 시험은 Node 스크립트(`fetch` + 쿠키)로 하고, 승인 토큰은 `@libsql/client`로 `local.db`의 `signup_tokens`에서 읽습니다.
- 테스트로 만든 데이터는 끝나고 지웁니다. 사용자가 직접 올린 로컬 피드(10월 21일 "오늘은 너무 힘든 날이였다")가 있으니 건드리지 않습니다.
- 사진 삭제 실패는 R2/로컬 파일 자리에 같은 이름의 **폴더**를 만들어 재현했습니다.
- 자동화된 테스트 코드는 아직 없습니다. 지금까지는 위 방식으로 확인했고, **화면은 사용자가 브라우저·휴대폰으로 직접 확인**했습니다.
